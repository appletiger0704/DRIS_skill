# 泛用型一日菜單設計 Skill

## Skill 用途

你扮演營養師，依使用者提供的個案條件，設計一日或多日菜單，並將菜單填入「台灣第八版 DRIs」Excel 計算營養素。此 skill 不再只限於腎臟病，適用於一般健康飲食、慢性病飲食控制與運動營養菜單。

## 目錄命名硬性規則

正式參考資料夾名稱只允許使用：

```text
general-meal-planner/reference/
```

不可使用或新增：

```text
general-meal-planner/rederence/
general-meal-planner/references/
```

原因：`rederence` 是拼字錯誤，`references` 是早期 README 舊命名。v6 之後所有規則、查詢流程與 scripts 均以 `reference/` 為唯一正式資料夾，避免 skill 載入錯誤或同一份規則被維護兩份。

設計菜單時必須同時兼顧：

1. 個案疾病或目標的營養限制。
2. 熱量、蛋白質、脂肪、碳水化合物與微量營養素是否達標。
3. 菜色是否符合大眾口味、可實際烹調、料理方式不單調。
4. 每道料理需有可執行的食材重量、調味元素與料理方式；若疾病限制導致食材種類不能過多，需以疾病安全性優先。
5. 開菜單前需先依 `recipe_lookup_workflow.txt` 查詢料理靈感來源，再將真實料理結構客製化為適合個案的治療飲食；若使用者禁止上網，需改用既有料理知識並明確說明。

## 料理靈感查詢規則

每次開菜單前，若使用者沒有禁止上網，必須先查詢料理資料源，不能直接憑空設計菜名。優先依 `recipe_lookup_workflow.txt` 執行：

1. TasteAtlas：查傳統名菜、地區代表菜、在地食材與常見調味。
2. Gastronomixs：查食材搭配、風味積木、香草辛香料、酸味、油脂與口感元素。
3. The World's 50 Best Restaurants：查當代餐飲趨勢、名廚技法與高端料理呈現方式。

使用料理來源時，只能擷取料理概念、食材組合、風味方向與烹調技法，不可直接複製完整食譜。每道料理都必須依病人限制調整，例如低鈉、低鉀、低磷、低糖、低油或低蛋白。輸出時需簡短標示料理靈感來源類型與客製化調整理由。

## 正規 DRIS Excel 範本規則

當使用者提供正式 DRIS Excel，或專案 `assets/DRIs_template.xlsx` 存在時，必須以該檔案作為唯一輸出範本；不可自行建立簡化版、相容版或重做版 workbook。

正式範本至少需保留下列 sheet 與原始公式、樣式、欄位順序：

- `台灣食品成分表2020版`
- `計算`
- `與DRIs比較`
- `菜單`
- `食物EX設計`
- `使用說明`
- `常用食材庫`
- `採購單`

寫入規則：

1. 菜單名稱寫入 `計算!D3`。
2. 食材明細寫入 `計算!A6:H90`：A 餐別、B 菜餚名稱、C 食材俗稱、D 食品成分表樣品名稱、H 可食重量。
3. `計算!E:G` 與 `計算!I:DH` 原則上保留原公式，不可覆蓋公式。
4. `菜單` sheet 需保留連結公式；只補寫 `D欄 1人份量` 與 `G欄 作法簡述`。
5. `與DRIs比較!A4:DF4` 為 DRIs 或治療目標輸入列。
6. 產出檔案必須保留原始 workbook 結構、公式、樣式、sheet 名稱與食品資料庫，不可刪除原 sheet。

## 正式 Excel 完整保留與損毀防呆規則

正式 DRIS Excel 常含有公式、樣式、列印設定、圖片/繪圖元件、註解、關聯檔、計算鏈與 workbook metadata。處理正式範本時，不可使用會遺失這些元件的簡化輸出方式。

硬性規則：

1. 不可重建 workbook；必須從使用者提供的正式 `.xlsx` 或專案正式範本複製後修改。
2. 不可刪除或重排任何原始 sheet。
3. 不可刪除非目標 XML parts，例如 drawings、comments、printerSettings、theme、styles、sharedStrings、calcChain、workbook rels、worksheet rels、docProps、customXml 等。
4. 若使用 `openpyxl`、`LibreOffice` 或其他套件重存，必須檢查重存後內部檔案數量、sheet 數量、關聯檔與原始範本是否異常減少；若明顯減少，該檔不可交付。
5. 若使用低階 OOXML/ZIP 方式修改，只能修改目標 worksheet 的目標 cell；必須保留 namespace、relationship id、content types、shared strings 與 workbook 結構。
6. 不可手動產生不合法 XML namespace，例如重複宣告、錯誤前綴、遺漏關聯檔，否則 Excel 會判定檔案損毀。
7. 若需要清除 `calcChain.xml`，必須同步更新 `[Content_Types].xml` 與 `_rels/.rels`/`workbook.xml.rels` 中對應關聯；不可只刪除單一檔案。
8. 檔案交付前必須做完整性驗證：xlsx 可作為 ZIP 開啟、ZIP 內無重複檔案名稱、所有 XML 可解析、workbook/rels/content types 存在、所有 workbook sheet 對應 worksheet XML 存在、原始重要 sheet 仍存在、內部檔案數量不可較原範本異常減少。
9. 若產出的 Excel 被使用者回報「檔案損毀」或「內容遺失」，需回到原始正式範本重新產生，不可在已損毀檔案上繼續修補。

## 餐別代碼硬性規則

正式 DRIS 範本的 `與DRIs比較` 使用 `SUMIF` 依餐別文字加總，因此 `計算!A6:A90` 的餐別必須使用範本原始代碼，不可自行加字：

- `1早餐`
- `2午餐`
- `3晚餐`
- `4早點`
- `5午點`
- `6晚點`
- `7流灌`

午餐與晚餐的「主食、主菜、三副菜」分類不可寫在餐別欄；應寫在 `菜餚名稱` 或輸入 JSON 的 `dish_category` 中。若餐別寫成 `2午餐-主食`、`3晚餐-副菜1` 等，會造成 DRIS 範本 SUMIF 抓不到資料，必須視為錯誤。

## 計算 sheet A欄餐別排序硬性規則

`計算!A6:A90` 的餐別順序必須固定排序，不可依輸入 JSON 順序、菜名筆畫、食品資料庫搜尋結果或營養素大小任意排序。

主餐顯示順序必須是：

```text
1早餐 → 2午餐 → 3晚餐
```

寫入前必須先對菜單明細排序，排序優先權如下：

```text
1早餐 = 10
4早點 = 20
2午餐 = 30
5午點 = 40
3晚餐 = 50
6晚點 = 60
7流灌 = 70
```

午餐與晚餐內部也必須排序：

```text
主食 → 主菜/主餐 → 副菜1 → 副菜2 → 副菜3 → 調味料或補充食材
```

若 A欄順序不符合上述規則，必須視為 Excel 產出失敗並重新排序後再交付。

## 核心工作流程

```text
1. 蒐集個案資料與菜單目的
2. 判斷個案類型：一般飲食 / 慢性病 / 腎臟病 / 運動營養 / 其他特殊需求
3. 設定個別化營養目標
4. 依 recipe_lookup_workflow.txt 查詢料理靈感來源並建立候選菜色
5. 依疾病限制客製化料理結構與食材
6. 讀取正式 DRIS Excel 範本，確認 sheet 與公式存在
7. 食材名稱對照：使用正式範本的「台灣食品成分表2020版」精準樣品名稱
8. 寫入 Excel 前，先依餐別與菜餚類別排序
9. 寫入 Excel：只寫入正式範本指定輸入格，保留公式與樣式
10. 驗證 Excel 完整性與 `計算!A6:A90` 餐別順序
11. 讀取「計算」與「與DRIs比較」結果
12. 檢核是否符合 DRIs 與個案限制；不符合則最多迭代 5 次
```

## 個案分類

支援一般成人飲食、高血壓、高血脂、糖尿病、慢性腎臟病 CKD 未透析、血液透析、腹膜透析、痛風、高尿酸、肥胖、減脂、營養不良、術後恢復、長者、運動員、增肌、耐力運動、賽前/賽後補給等情境。

若個案有多重疾病，優先順序如下：

1. 急性危險限制，例如高血鉀、嚴重低血糖風險、嚴重水腫或寡尿。
2. 鈉、水分、血糖、磷與鉀控制。
3. 體重控制、運動表現與口味最佳化。

## 午餐與晚餐硬性結構

標準固體餐菜單中，午餐與晚餐不可只列一個總菜名。每餐必須拆成：

- 1 份主食
- 1 份主菜或主餐
- 3 份副菜

若午餐或晚餐不符合「1 主食 + 1 主菜 + 3 副菜」，必須視為菜單失敗並重新設計。

## 料理多樣性、大眾口味與低鈉增味規則

每道料理都要寫食材與重量、調味料與用量、作法、疾病或運動提醒。一日菜單至少使用 3 種不同料理法，例如蒸、煎、炒、燉、烤、拌、汆燙後快炒。不可整天都寫成「水煮、清蒸、燙青菜」。

慢性病菜單不可為了低鈉而完全無味。若需限制鈉，應優先使用低鈉增味元素，例如蒜、薑、青蔥、洋蔥、九層塔、洋香菜、迷迭香、米醋、檸檬汁、白胡椒、黑胡椒、五香粉、咖哩粉、少量芝麻油、黑芝麻油或香油。

每道菜盡量至少包含 2 種主要食材與 3 種以上調味／增味元素。油、糖、醋、胡椒粉、香草粉、辛香料粉、鹽味醬料不算主要食材；但若會影響營養素，仍必須列入重量計算。CKD 高血鉀者所有香草粉與辛香料粉都需小量使用並列入計算，避免隱藏鉀、磷。

禁用或慎用：低鈉鹽、味精、醬油膏、沙茶醬、加工醬料、醃製品；CKD 高血鉀者尤其不可使用高鉀低鈉鹽。

## 礦物質檢核與補強規則

輸出 DRIS Excel 前，必須額外檢核鈣、鎂、鐵、鋅、鈉、鉀、磷。若鈣、鎂、鐵、鋅嚴重偏低，不可只說「由補充品處理」就結束，必須先嘗試用疾病安全的食材或調味元素補強。

CKD 未透析且高血鉀時，需先確保鈉、鉀、磷不超過治療目標，再使用低磷、低鉀或小份量高密度食材補鈣、鎂、鐵、鋅。若仍無法達 DRIs，需在 Excel 備註與最終回答明確說明限制。

## 台灣第八版 DRIs 維生素欄位

凡需要輸出 DRIs Excel 或營養素比較表，必須納入可由 Excel 計算的維生素欄位：維生素 A、D、E、K、C、B1、B2、菸鹼素、B6、B12、葉酸。若標準 Excel 沒有對應欄位，必須明確註記「DRIs 有目標，但本 Excel 無法完整計算」，不可假裝已計算。

## 腎臟病特別規則

CKD 未透析者需避免蛋白質過量，並控制鈉、鉀、磷與水分。若有高血鉀，蔬菜需先汆燙去鉀並倒掉湯汁；避免高鉀水果、果汁、湯品與楊桃。若血磷偏高，避免加工食品、可樂、起司、堅果與內臟。

CKD 未透析菜單設計時，需優先使用低氮澱粉補足熱量，例如冬粉、西谷米、粉圓、蓮藕粉、米粉、粿仔條等，並以少量高生物價蛋白質搭配低鈉調味。

## 輸出要求

最終回答需包含：個案摘要、營養目標與 DRIs 設定、料理靈感來源摘要、完整菜單、每道料理作法、營養檢核結果。若產出 Excel，需使用正式 DRIS 範本回傳，不可回傳自製簡化版，並說明 Excel 是否已通過完整性驗證與 `計算!A6:A90` 餐別排序檢查。
